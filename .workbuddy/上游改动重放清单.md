> **这份文档的唯一用途**：拿到上游新版本后，照着它把本地补丁逐条重新落一遍。
> 它不记录「什么时候推的、CI 几号绿」——那些在 `修改清单.md`（历史与证据）。
>
> **基线**：上游 `v3.4.2`（主包 `aimod-cc/Agent2API` = `e8bed739`；插件
> `ProvidersPlugin/Agent2Providers` = `3055f416`）。
> **基准点**（算差异用的 commit）：插件 `f55ab15b`（上游 v3.4.2 镜像导入）、
> 主包 `96d266a0`（同上）。
> **当前落点**：已重放到上游 **`v3.5.0-beta.1`** 并**已推送** ——
> 主包 `2ad6fe4b`（合并）+ `6ebb1edf`（workflow 由 API 补）→ `main-patched`；
> 插件 `71783c06` → `plugin`。
> 上一轮落点（v3.4.2 基线）为 主包 `8d0e43e4` / 插件 `9b476f75`。
>
> **v3.5.0-beta.1 重放结果速览**（详见 §8）：
> 采上游 5 处（cloud_sync / officeace / qoder / provider-icons / rpc 分类）、
> 保本地 8 类独有能力、i18n 20 个源文件键级合并、产物全部重建、
> 锚点核对 `63 / 0`。
>
> ⚠️ **§3.7 是另一码事，别混进来**：上面 107 个文件是「本地对上游补丁」，
> 记忆中枢是**上游完全没有的自研模块**（30 个新文件 `+26784` + 20 个挂载点
> `+379 −24`）。它永远不会出现在 `git diff <旧tag> <新tag>` 里，
> 只按 §2/§3 干活会让它**静默整块消失**（不报错，页面点进去是空白）。
> 拿到新版先看 §3.7。

## 0. 怎么用（拿到新版上游时的操作顺序）

1. **先算「上游这一版动了哪些文件」**，不要一上来就合并。

   ```bash
   # 插件
   git diff --name-only <旧上游tag> <新上游tag> > /tmp/up_plugin.txt
   # 主包
   git diff --name-only <旧上游tag> <新上游tag> > /tmp/up_main.txt
   ```

2. **与本文 §2 / §3 的文件清单求交集**。交集 = 需要重新裁决的文件；
   不交集 = 上游没碰，本地补丁可以原样留着，不用管。

   > ⚠️ **这一步会漏掉记忆中枢**。它在上游根本不存在，所以永远不进交集。
   > 走完 §2/§3 之后必须**单独做 §3.7**：整块搬 30 个文件 + 重贴 20 个挂载点。
   > 漏了不会报错 —— 编译能过、页面能开，只是「记忆中枢」菜单点进去一片空白。

3. **交集里逐个看三种情况**：

   | 情况 | 判据 | 处理 |
   |---|---|---|
   | 上游没碰这块逻辑 | 本文的「改动锚点」在新版里还找得到 | 本地补丁直接沿用 |
   | 上游改了相邻代码，但没改这块 | 锚点在，但上下文变了 | 手工重贴，按「判据」验 |
   | 上游**自己也修了**同一件事 | 锚点整段消失、或上游代码里出现等价逻辑 | **采上游、删本地**（本文标注了哪些属于这类） |

4. **产物不手改，跑 §4 的重建命令**。

5. **跑 §5 的核对脚本**，锚点全在才算重放完成。

```rust
pub const SERVICE_IDS: [&str; 4] = [..., MEMORY_SERVICE_ID];
pub const CAPABILITY_COUNTS: [(&str, u32); 3] = [..., (MEMORY_SERVICE_ID, 16)];
pub const DEFAULT_TIMEOUTS: [(&str, u64); 4] = [..., (MEMORY_SERVICE_ID, 30)];
```

三处长度数字必须与元素个数一致，**少改一个数字就编译错**（好在是编译错，不是静默）。
但反过来，`CAPABILITY_COUNTS` 里漏掉记忆那一项**不会**编译错 —— 数组长度对得上，
只是接入页显示的「能力数」少一个。重放时优先核对这三行。

## 7. 已知陷阱（重放时最容易翻车的 13 处）

1. **`doubaowork/mod.rs` 0 冲突也有毒** —— 见 §2.2。每次合并后必看三处。
2. **上游重构过的 provider 目录不能混编** —— 要么整套取上游，要么整套保留。
   v3.4.1 时 `trae` 留了 4 个本地文件 → 7 个编译错。
3. **CRLF 会让合并退化成整文件替换** —— 造合成 commit 时三步都要
   `-c core.autocrlf=false`，且 ours 先做 `\r\n → \n` 归一。
   判据：`git status --porcelain | grep -c '^ D'` 必须为 0。
4. **`restore --worktree` 会漏文件** —— 合并后补 `checkout-index -a -f`。
5. **SDK 增量字段会打断本地保留文件** —— 合并前先 diff
   `crates/provider-sdk/**`，本地文件里手写的结构体构造点会缺字段。
6. **改枚举载荷类型要全局 grep `Variant(`** —— `3d144571` 把
   `Failed::Rejected(u16)` 改成 `String`，漏了 `portal_session.rs:377`
   一个构造点，CI 才抓到（本机没 Rust 工具链，CI 是唯一编译器）。
7. **同名 tag 在两仓冲突**（v3.5.0-beta.1 实证）—— 主包与插件都有
   `v3.4.2` / `v3.5.0-beta.1`，本地 tag 命名空间只能指向一个仓库。
   **不要 `git fetch --tags`**，用自定义 ref 分开取：

   ```bash
   git fetch upstream-plugin \
     refs/tags/v3.4.2:refs/up/plugin-v3.4.2 \
     refs/tags/v3.5.0-beta.1:refs/up/plugin-v3.5.0-beta.1
   ```

8. **镜像 commit 的父必须接在上一个镜像上** —— 否则 `merge-base` 为空，
   合并退化成 686 个 add/add 冲突（v3.5.0-beta.1 实证）：

   ```bash
   # 主包：以 v3.4.2 镜像（96d266a0）为父
   git commit-tree "v3.5.0-beta.1^{tree}" -p 96d266a0 -m "upstream: v3.5.0-beta.1 (mirror import)"
   # 插件：以 v3.4.2 镜像（f55ab15b）为父
   git commit-tree "$PLUG_TREE" -p f55ab15b -m "upstream: plugin v3.5.0-beta.1 (mirror import)"
   ```

9. **插件镜像 tree 必须带 `provider-plugins/` 前缀** —— 上游插件仓库根就是
   crates 目录，本地是 `provider-plugins/` 子目录。直接把上游 tree 写进本地
   会触发整目录 rename/delete。用临时 index 重写：

   ```bash
   TMPIDX=$(mktemp)
   GIT_INDEX_FILE="$TMPIDX" git read-tree --empty
   GIT_INDEX_FILE="$TMPIDX" git read-tree --prefix=provider-plugins/ refs/up/plugin-v3.5.0-beta.1
   NEWTREE=$(GIT_INDEX_FILE="$TMPIDX" git write-tree)
   ```

10. **`ui-kit` 依赖不装，typecheck 会炸出几百条假错误**（v3.5.0-beta.1 实证）——
    `ui-shared/**` 与 `ui-kit/src/**` 共用 `@base-ui/react`、`clsx`、
    `tailwind-merge`，这些装在 `desktop-tauri/ui-kit/node_modules`。
    ui-islands 只装自己的 `npm ci` 时，跨包 import 全部 TS2307，
    连带 `noImplicitAny` 把每个回调参数都报成 TS7006 —— 实测 **365 条假错误**。
    正确处理顺序：

    ```bash
    npm --prefix desktop-tauri/ui-kit ci          # 先！提供 base-ui / clsx / tailwind-merge
    npm --prefix desktop-tauri/ui-islands ci
    npm --prefix desktop-tauri/mobile ci
    npm --prefix desktop-tauri/i18n ci
    npm --prefix desktop-tauri/ui-islands run build   # 此时才应该 0 error
    ```

    判据：`npx tsc --noEmit | grep -c "error TS"` 必须为 `0`。
    如果还剩 TS1117（重复键），那是合并真错，别当环境问题糊过去。

11. **PAT 缺 `workflow` scope，推不了 `.github/workflows/**`**（2026-11-15 实证）——
    本地 classic PAT 只有 `public_repo`，push 时报：

    ```text
    ! [remote rejected] (refusing to allow a Personal Access Token to create or
       update workflow `.github/workflows/xxx.yml` without `workflow` scope)
    ```

    **注意不是 403/404，是「remote rejected」**，而且整条 ref 更新一起失败
    （不会只跳过那个文件）。处理顺序：

    1. 先探：`curl -sI -H "Authorization: token $T" https://api.github.com/user | grep -i x-oauth-scopes`
       —— 不含 `workflow` 就必然失败。
    2. 造一个「摘掉 `.github/workflows` 改动」的等价提交推上去：用临时 index
       `read-tree` 目标提交 → `update-index --force-remove <路径>`（或把被删的
       文件 `--add --cacheinfo` 补回）→ `write-tree` → `commit-tree`（父节点保持原样）。
    3. 再用 GitHub 连接器的 `create_or_update_file` / `delete_file` 单独补那几个
       workflow 文件（连接器有独立授权，能写）。
    4. 校验：`git rev-parse <原提交>^{tree}` 与 `git rev-parse origin/<branch>^{tree}`
       **必须相同** —— 相同就说明 API 补的文件与本地 blob 字节一致。
    5. 最后 `git reset --hard origin/<branch>` 让本地对齐（否则本地领先/落后会误判）。

12. **插件镜像会把仓库根的 `.gitignore` / `.github/` 当成「上游删除了」**（2026-11-15 实证）——
    插件镜像把上游根映射成我们仓库根，于是上游根没有的文件，在 merge 里表现为
    **删除**。这次就误删了 `plugin` 分支根上的 `.gitignore`（3 行）和
    `.github/workflows/plugin-build.yml`（92 行）——**这两个是 fork 自己的，不是上游的**。

    判据（每次插件合并后必查）：

    ```bash
    git ls-tree --name-only plugin        # 必须看到 .github  /  .gitignore  /  provider-plugins
    ```

    修复：从上一个插件落点取 blob 补回，再一起提交：

    ```bash
    GI=$(git rev-parse <旧插件tip>:.gitignore)
    GW=$(git rev-parse <旧插件tip>:.github/workflows/plugin-build.yml)
    # 临时 index：read-tree 合并结果 → update-index --add --cacheinfo 100644,$GI,.gitignore
    #            → 同样补 workflow → write-tree → commit-tree（父 旧tip + 镜像）
    ```

    ⚠️ 反过来，`provider-plugins/.github/{workflows/build.yml,actions/sign-pack/}`
    是**本地有意删除**的（我们不签名），合并把它们保持删掉是**对的**，不要手贱补回来。

13. **锚点全绿也可能编不过**（2026-11-15 实证：`63/0` + `tsc 0 error`，`cargo` 三平台全挂）——
    典型形态是**上游改了函数签名**（加参数、改返回、改模块归属），本地补丁还在按旧签名
    调用。`grep` 关键字永远命中，所以锚点核对查不出来。必须真编译：

    ```bash
    # 主包（main-patched 不在 push 触发面）
    curl -s -X POST -H "Authorization: token $TOKEN" \
      -H "Accept: application/vnd.github+json" \
      "https://api.github.com/repos/liu6617243/agent2api/actions/workflows/419160669/dispatches" \
      -d '{"ref":"main-patched"}'
    ```

    已知的三类签名漂移（下次重点看）：事件事实表 `credit_slot` → `usage_slot` +
    `UsageFacts` 结构体；`content_hash(key: Option<&[u8;32]>)`；`attempt_stateful(...,
    budget: &mut RetryBudget)`。
