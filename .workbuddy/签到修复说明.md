# 豆包工作 / 小浣熊 签到修复说明

## 一、现象（来自 `~/.agent2api/agent2api.db` → `checkin_records`）

```
日期        家         结果     文案
2026-10-29  raccoon    pending  今日未见积分入账，尚未确认领取
2026-10-29  raccoon    success  今日积分 +300          ← 同一天下一行：用户手点才补上
2026-10-30  raccoon    pending  今日未见积分入账，尚未确认领取
2026-10-30  doubaowork failed   豆包工作：领取结果确认中，请稍后重试
```

这两行的共同点：**都不是真失败，而是「此刻还没出结果」**。旧代码把它们
分别判成 pending 与 failed，而 pending/failed 都不会自动重来 —— 所以用户看到
的就是「签到总是有问题」。

## 二、三个根因

### 1. 小浣熊：异步入账，同步查账单（判 pending）
`setting_info` 只是**触发器**，服务端随后才把积分记进账单（实测 21～31 秒后到账）。
旧代码触发完立刻查 bills，必然查空，于是判「今日未见积分入账」。

### 2. 豆包工作：异步受理被当成致命错误（判 failed）
上游返回 `biz_error.msg = "领取结果确认中，请稍后重试"`，语义是**已受理、结果待定**。
但 `receipt()` 只容忍 biz_error code `0 | 4 | 6`，其余一律 `Err(api::error(...))`，
于是整场签到被判 failed。
> 该文案来自豆包服务端，「豆包工作：」前缀是插件加的 —— 不是插件自己写的错误。

### 3. 共同放大器：没给 `claim.retryAt`
网关 `auto_checkin/retry.rs::retry_at()` 只在 `claim.retryAt` 存在、或 provider 是
qoder/codearts 时才排重试。豆包和浣熊**从不给**这个字段，所以 pending 只能等用户手点。

而 SDK 的默认实现 `checkin_with_options` = `checkin(...).map(Into::into)`，
**会把 `retry_at` 丢掉** —— 每家必须重写它才能透传（zcode 是样板）。

## 三、改动（4 个文件）

| 文件 | 改动 |
|---|---|
| `raccoon/balance.rs` | 抽出 `GrantCheck` + `check_today_grants()`；首查空则等 15s 复核一轮；仍空则写 `claim.retryAt = now + 10min` |
| `raccoon/mod.rs` | 重写 `checkin_with_options`，把 `retryAt` 送进 `CheckinResult.retry_at` |
| `doubaowork/rewards.rs` | `Receipt` 三态（Confirmed/Unconfirmed/**Accepted**）；`settled_later()` 识别受理态；受理态等 8s 再回查；回查失败/未确认改报中性 `Inactive` + `retryAt`，不再 failed |
| `doubaowork/mod.rs` | 重写 `checkin_with_options` 透传 `retryAt`；`checkin` 只取 `.report` |

### 一处反直觉的修复细节
受理态常常**与 `success: false` 一起返回**（「确认中」本来就不算成功）。
原代码先判 `success == false` 就报「领取被拒绝」，会把可恢复的异步态打死。
现在**先读 `biz_error`，再判 success**。

## 四、时间预算（都不超网关超时）

- 小浣熊：首查 ~9s + 等待 15s + 复核 ≤25s ≈ **50s**
- 豆包：claim + 等待 8s + 回查 ≈ **30s**
- 网关 `checkin.claim` 走 network 通道 = `NETWORK_TIMEOUT = 120s`（`rpc.rs:51`）

## 五、修复后行为

| 场景 | 旧 | 新 |
|---|---|---|
| 浣熊积分晚 15s 内到账 | pending（等人手点） | **Claimed，+N 积分** |
| 浣熊 30s 后才到账 | pending（永不重试） | Inactive + retryAt → **10 分钟后自动复核** |
| 豆包「确认中」且 8s 内出结果 | failed | **Claimed** |
| 豆包「确认中」仍未出结果 | failed | Inactive + retryAt → **10 分钟后自动复核** |
| 豆包真失败（库存不足等） | failed | failed（**保持不变**） |
| 豆包已签过 | Done | Done（**保持不变**） |
